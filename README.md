# Рукша Мебель: бот заказов

Telegram-бот для трекинга заказа по этапам: замер → дизайн → раскрой → сборка → монтаж.

## Запуск

Нужны Node.js 22.13+ и токен бота от @BotFather. Зависимостей нет.

```
BOT_TOKEN=... DIRECTOR_ID=123456789 npm start
```

- `BOT_TOKEN` — токен бота. В код и в репозиторий не кладём.
- `DIRECTOR_ID` — Telegram ID директоров через запятую. При каждом запуске получают роль «директор» и утреннюю сводку в 08:30 по Минску: просрочено, на сегодня, открытые заказы с этапами. Не задан и директоров в базе нет — доступа нет ни у кого.
- `DB_PATH` — файл базы, по умолчанию `./data/orders.db`.

Остальных сотрудников директор добавляет в самом боте командой `/staff`. Раньше доступ давал список `ALLOWED_IDS`: он больше не используется, сотрудников надо добавить заново.

## Роли и права

| Роль | Создаёт заказы | Видит заказы | Закрывает этап |
| --- | --- | --- | --- |
| директор | да | все | любой |
| менеджер | да | все | замер |
| дизайнер | нет | где сейчас дизайн | дизайн |
| оператор_чпу | нет | где сейчас раскрой | раскрой |
| сборщик | нет | где сейчас сборка | сборка |
| монтажник | нет | где сейчас монтаж | монтаж |

Заказ вне очереди роли бот не показывает, а на несуществующий номер отвечает так же: «нет в вашей очереди». Номер угадать нельзя. Правило видимости собрано в одной функции (`canViewOrder` в `src/staff.js`), его легко поменять. Роль проверяется списком в коде (`ROLES` в `src/stages.js`), поэтому новая роль в фазе 2 не требует перестройки базы.

Человек без доступа получает ответ «Нет доступа» со своим Telegram ID, чтобы передать его директору, и больше ничего не видит.

## Команды

- `/new Имя клиента | заметка` — новый заказ (менеджер, директор)
- `/list` — открытые заказы, которые вам видны
- `/order 3` — карточка заказа №3
- `/done 3` — отметить текущий этап выполненным (его роль или директор)
- `/call 3 2026-10-12 10:00 позвонить, уточнить размеры` — задача с напоминанием в срок (время по Минску, UTC+3)
- `/tdone 5` — отметить задачу №5 выполненной (только исполнителю)
- `/staff` — список сотрудников (директор)
- `/staff add 123456789 монтажник Иван` — добавить или сменить роль (директор)
- `/staff off 123456789`, `/staff on 123456789` — отключить и включить (директор). Себя менять и отключать нельзя. История «кто закрыл этап» сохраняется.

Напоминания и сводка проверяются раз в минуту. Сводка уходит один раз в день, даже после перезапуска бота, всем активным директорам. Если отправка не удалась, повтора не будет: лучше пропустить, чем дублировать. Напоминание получит только тот, кто хотя бы раз написал боту (правило Telegram).

## Проверка

```
npm test
```

Руками: запустите бота с вашим `DIRECTOR_ID`, отправьте `/new Тестовый Клиент | проверка`. Попросите коллегу написать боту, возьмите ID из ответа и добавьте: `/staff add ID дизайнер`. Дизайнер не должен видеть заказ, пока менеджер не закроет замер, и не должен закрыть чужой этап.

## Что ещё не сделано

- Хранилище — файл SQLite. На хостинге без постоянного диска файл теряется при каждом редеплое: нужен диск (на Railway это Volume) или переход на Postgres. Переход потребует переписать работу с базой на асинхронную и проверить её на настоящем Postgres.
- Персональные данные клиентов (имя, телефон, адрес): политика, согласие и место хранения. По Указу №60 хостинг может быть обязательным в Беларуси. Проверить у юриста до сбора реальных данных.
- Node-модуль `node:sqlite` помечен экспериментальным в Node 22: при обновлении Node проверить.
- Фазы 2–4 (технолог и спецификация, финансы, аналитика) не начаты.

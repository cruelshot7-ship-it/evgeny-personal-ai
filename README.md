# Рукша Мебель: бот заказов

Telegram-бот для трекинга заказа по этапам: замер → дизайн → раскрой → сборка → монтаж.

## Запуск

Нужны Node.js 22.13+ и токен бота от @BotFather. Зависимостей нет.

```
BOT_TOKEN=... ALLOWED_IDS=123456789 npm start
```

- `BOT_TOKEN` — токен бота. В код и в репозиторий не кладём.
- `ALLOWED_IDS` — Telegram ID тех, кому разрешено пользоваться ботом, через запятую. Пусто — доступа нет никому.
- `DB_PATH` — файл базы, по умолчанию `./data/orders.db`.
- `DIRECTOR_ID` — Telegram ID директора. Получает утреннюю сводку в 08:30 по Минску: просрочено, на сегодня, открытые заказы с этапами. Не задан — сводки нет.

## Команды

- `/new Имя клиента | заметка` — новый заказ
- `/list` — открытые заказы
- `/order 3` — карточка заказа №3
- `/done 3` — отметить текущий этап выполненным
- `/call 3 2026-10-12 10:00 позвонить, уточнить размеры` — задача с напоминанием в срок (время по Минску, UTC+3)
- `/tdone 5` — отметить задачу №5 выполненной (только исполнителю)

Напоминания и сводка проверяются раз в минуту. Сводка уходит один раз в день, даже после перезапуска бота. Если отправка не удалась, повтора не будет: лучше пропустить, чем дублировать. Напоминание получит только тот, кто хотя бы раз написал боту (правило Telegram).

## Проверка

```
npm test
```

Руками: добавьте бота, отправьте `/new Тестовый Клиент | проверка`, затем `/done 1` пять раз. Заказ должен закрыться, `/list` должен его больше не показывать.

## Что ещё не сделано

- Роли и права: сейчас доступ только по списку ID, роль не проверяется.
- Персональные данные клиентов (имя, телефон, адрес): политика, согласие и место хранения. По Указу №60 хостинг может быть обязательным в Беларуси. Проверить у юриста до сбора реальных данных.
- Node-модуль `node:sqlite` помечен экспериментальным в Node 22: при обновлении Node проверить.
